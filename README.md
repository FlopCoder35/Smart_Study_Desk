# SitRight | Live dashboard for your existing Arduino sketch

This is a dashboard-only update. Keep your latest Arduino sketch; no firmware replacement, no Telegram service and no pip packages are required. The dashboard reads ThingSpeak, not the serial port, and never writes readings or sends Telegram messages.

## Start
1. Enable all 8 fields on the ThingSpeak channel associated with the Arduino WRITE_KEY (see table below).
2. Make sure ESP32 uploads succeed: Serial Monitor at 115200 should show `ThingSpeak HTTP 200 | entry: <positive integer>`.
3. Extract this ZIP into its own folder. Run `Start_Dashboard.bat` on Windows or `python app.py` (Python 3.9+). Open http://127.0.0.1:8765.
4. Click Connection settings and enter Channel ID and Read API Key (blank for public channel). Select Demo (30 sec), matching your current Arduino sketch. Save & connect.
5. Check the latest entry ID and mapping table against the same ThingSpeak channel. Dashboard polls every 10 sec and the sketch attempts uploads every 20 sec. No sample data is generated by this release.

| Field | Source |
|---|---|
| 1 | lastDist in cm |
| 2 | sitMs / 60000.0 (minutes, two decimals) |
| 3 | lastTemp in °C |
| 4 | lastHum in % |
| 5 | status: 0 normal, 1 too close, 2 break due (highest priority) |
| 6 | present: 0/1, inferred from PIR motion |
| 7 | warnCount, since boot |
| 8 | notifyCount, successful reminder HTTP 200 responses since boot, excluding startup |

Demo: 30-second break, 10-second PIR presence hold, 15-second away reset. Normal mode: 25 minutes, 120-second hold, 300-second reset. Both: 40 cm threshold for 5 seconds, 20-second uploads, 10-second failed-notification retry. The dashboard setting does not change device firmware.

## Verify integration
- Sit with movement at ~60 cm; field 6 becomes 1, field 5 is 0 before break threshold.
- Lean to ~25 cm for 5 sec before the break threshold. Red LED, Telegram posture alert; field 7 increases, field 8 increases if Telegram returns HTTP 200.
- Remain present until 30 sec. Red/green alternate and a break alert is sent once; field 5 becomes 2.
- Leave until the PIR has been low long enough for the reset. Field 2 returns to zero and field 5 to 0. Field 7 and 8 remain cumulative until ESP32 restarts.
- Match serial monitor entry ID, ThingSpeak data, and dashboard entry ID. Hold a state across an upload to see it on the dashboard. A quick event may only be visible in counters.

## Important limitations of the supplied sketch
- It initializes distance to 100 cm and temperature/humidity to 0, and retains prior successful values on read failure. There is no validity flag, so the dashboard cannot verify sensor health from the eight fields.
- A break can remain latched after presence becomes 0 until the absence reset. Display follows field 5, not a new browser-generated alert rule.
- Telegram field 8 counts API HTTP 200 responses, not phone read receipts or exact message history. Pending flags can coalesce multiple warnings if offline, and blocking network calls can delay sensing/LED changes. No exact event timestamps, pending queue status, or GPIO feedback are sent to ThingSpeak. LED animations are indicative, not phase synchronized. The timer is sampled, not extrapolated.
- Older readings are marked stale at >65 sec. Charts use the latest 100 entries; range selections are relative to latest cloud entry. Activity is inferred from changes, not a complete event log. CSV contains selected readings.
- Your code sends the Write Key over plain HTTP and disables Telegram TLS certificate verification. Rotate the exposed ThingSpeak Write API Key, Telegram bot token and Wi-Fi password; update your sketch locally. For production use verified HTTPS. No write key, Wi-Fi password, Telegram token or chat ID is bundled in this dashboard. The optional Read API Key is stored locally in config.json, never returned to the browser; keep it private. Server is localhost only.

Live verification requires your Channel ID and, if private, Read API Key. No live sensor or notification delivery test is performed by the dashboard itself.
